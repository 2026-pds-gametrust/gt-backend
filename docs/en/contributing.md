# Contributing to documentation

How to keep project docs, HTTP API pages, and DeepWiki aligned. Portuguese: [pt-BR](../pt-BR/contributing.md).

English is normative for code identifiers, paths, and `ARCH-*` / `DEC-*`. Update **both** `docs/en/` and `docs/pt-BR/` for published pages. If they conflict, English wins.

## Surfaces

| Surface | You edit | Generated? |
|---------|----------|------------|
| Project docs | `docs/en/**`, `docs/pt-BR/**` (except `api/`) | No |
| HTTP API | Overlay copy in `scripts/generate-frontend-api-docs.js` + `src/contracts/service.yaml` | Yes — `yarn docs:api` |
| Architecture canon | `docs/architecture/`, `docs/entities/` | No (agents cite these) |
| DeepWiki | `.devin/wiki.json` | Wiki is generated by Devin / deepwiki.com |

Do not translate `docs/specs/`, `docs/ralph/`, or `docs/audits/`.

## How to document an endpoint

1. Change the route, body, query, or response in code **and** in [`src/contracts/service.yaml`](../../src/contracts/service.yaml).
2. Document `security` on the operation (`[]` = public; otherwise Bearer). Every route needs an explicit authorization decision.
3. Add or update the product overlay (`PRODUCT_GAIN`) in [`scripts/generate-frontend-api-docs.js`](../../scripts/generate-frontend-api-docs.js) for **en** and **pt-BR** if the OpenAPI summary is not enough for the frontend.
4. Run:

   ```bash
   yarn docs:api
   ```

5. Confirm the new folder exists under `docs/en/api/<module>/<resource>/<method-path>/` and the pt-BR mirror.
6. Link the operation from the module guide (`docs/en/modules/<module>.md`) if it is a new resource.
7. If the change is architectural (new module, new event, new auth rule), update `docs/architecture/` (`ARCH-*` / `DEC-*`) and the matching pages under `docs/en/architecture/` and `docs/pt-BR/architecture/` — especially [communication](./architecture/communication.md) and [messaging](./architecture/messaging.md).
8. New domain event: follow [messaging §How to add an event](./architecture/messaging.md#how-to-add-an-event) (envelope, handler in the consumer Service, `DomainEventRouterFactory`, both locales).
9. **DeepWiki** does not get a page per endpoint. After a meaningful architecture or module change, regenerate the wiki (below).

Generated files per operation (same names in both locales):

```text
README.md       # summary, auth, product gain, links to module
request.md      # request body
response.md     # success body + documented errors
parameters.md   # path / query / headers
examples.md     # fetch + what the client should do
curl.sh         # identical in EN and pt-BR
```

Do not hand-edit files under `docs/en/api/` or `docs/pt-BR/api/` — they are overwritten.

## DeepWiki

File: [`.devin/wiki.json`](../../.devin/wiki.json).

- `repo_notes` steer generation (GamerTrust, OpenAPI source of truth, SQS/SNS, layer spelling).
- `pages` is an **exclusive** list (max 30). Adding a page means listing **all** pages, not only the new one.
- Language: English (wiki is generated from code).
- Private repos: connect the repo in a Devin org and regenerate from the wiki UI.
- Public repos: replace `github.com` with `deepwiki.com` in the repo URL, or submit the URL at [deepwiki.com](https://deepwiki.com/).

After changing `.devin/wiki.json` or major architecture docs, regenerate the wiki so chat answers stay grounded.

## Checklist for a docs PR

- [ ] `service.yaml` matches the controller if HTTP changed
- [ ] `yarn docs:api` run; both locales updated
- [ ] Module guide links the new operation
- [ ] Product rules respected (no fake seals, Product ≠ Listing)
- [ ] No secrets or PII in examples
